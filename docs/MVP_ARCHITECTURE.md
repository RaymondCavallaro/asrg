# MVP Architecture

The MVP should prove one thing:

```text
Can hidden systemic pressure produce believable governance drama?
```

## Current Play Loop

1. The story starts from a seeded story dictionary.
2. The player configures the prince profile.
3. The opening council establishes pressure and threats.
4. The player selects a story node to inspect.
5. Contextual actions appear from the current scene and selected story node.
6. Actions create logs and structural effects.
7. Proxy cards convert logs into pressure.
8. The field generator propagates pressure through topology.
9. The reader samples partial knowledge.
10. The presenter turns that reading into text.

## MVP Systems

- One region.
- Six managed system nodes.
- Sparse pressure topology.
- Epistemic logs.
- Generic region reader.
- Template presenter.
- Contextual social actions.
- Visible action composition grammar.
- Story-node browser.
- Achievement screen with visible progress targets.
- Hidden debug dashboard for inspecting raw state during design.
- Hidden ACES state with qualitative presentation.
- Seeded JSON story dictionary.
- Local browser save.

## MVP Boundary

AI, multiplayer, CSP rules, imports, visible card composition, and rich story-pack tooling are future architecture. They should not expand the MVP until the core loop feels good.
